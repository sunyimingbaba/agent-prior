# UCM 工具末轮奖励对照

## 实验问题

对同一图像，给 Agent 第一轮生成的先验打分，或沿真实场景工具流程走到最后、给检索器实际接收的先验打分，是否会改变策略训练的效果？比较 R2 与同轮 R1、初始化 R0，以及上一轮同种子、同奖励的结果。主指标为 210 张 UCM 验证图、每图贪心生成一次的双向检索 mR，第二项验收为独立的数量、属性、空间判别题。负例池、真描述和所有标签只在相应的训练打分或事后读出时使用。

## 控制条件

两次配对实验分别取上一轮的 R0 权重及已归档的同一 R0 验证输出，核对 SHA-256。每个训练臂从对应 R0 开始，顺序处理同一批 24 张训练图，每图用场景提示以温度 1 采 8 条第一轮回答。初始权重、种子、图序、组内优势、格式分、AdamW、学习率 5e−6、裁剪范数 1 和固定末步检查点均沿用上一轮。每轮最多 64 个新 token，总共最多三轮。

如果第一轮结束，使用该轮最后一个有效动作的预测隐藏状态。如果发起工具调用，使用真实域内场景分类头回填结果，随后按部署设置贪心续写，把最终有效动作的预测隐藏状态交给评分器。在同一图、同一步和同一策略内，相同首轮动作共享确定性续写。日志保存首轮与最终先验的指纹、工具返回、续写 token 和逐项分数。

R1 用最终先验在重建的冻结代理评分器上计算原图排名倒数。R2 把最终先验交给冻结图文检索器，计算首条真描述比分数最高的训练负描述高多少，按该分差为 8 条候选排序；数值沿用本组最终先验的代理排名倒数分布，并列取均值。两臂的格式分沿用首轮规则，完整 answer 加 0.2。为单独比较奖励读出的位置，训练只对首轮随机采出的动作计算策略梯度；后续贪心动作负责确定这次首轮选择最终得到的奖励。参数在各轮共享。R1 与 R2 的部署及验收均使用相同的真实工具流程。

## 比较与诊断

固定 210 图、1,050 句的原图库，复算双向 R@1/5/10 及六项平均。两次结果均逐图配对，联合区间先在相同图上平均两个种子，再按图重采样 20,000 次。属性与空间题按自然图对重采样。记录 R2 相对上一轮的变化、R1 同期变化及二者之差。另外检查与输入首句 token 内容不同的 829 个验证描述，保留逐图原始结果。

在相同的 24 张训练图上，换新随机数重新采样，逐条走到工具流程结束，直接计算真实图文分差。上轮的 R1、R2 与本轮各臂均采用同样的重放条件，R0 同时与上轮逐候选归档交叉核验。这项检查回答训练策略是否更倾向于产生高分差的最终先验。固定训练步数，两次实验都使用既有验证集。

在两次主评估后补做回填后的候选诊断，仅用既有 24 张训练图和原始 R0。固定第一轮贪心输出和真实工具返回，为自然到达第二轮的输入重新采 8 个回答，再次调用工具时继续贪心到第三轮。R2 选择仍用首句与偶数负池的分差，R1 选择用最终先验的代理排名。独立读出使用其他真描述和奇数负池，统计最优替代真描述的 MRR。该诊断检查回填后的动作选择能否提供有用的训练信号。

## 复现与文件

服务端以每个种子的实验目录为工作目录，使用 code 中的脚本。R0 指向上一轮相同种子的已核实权重和验证输出。复制相应 initial.json 后，分别运行 `train.py R1` 和 `train.py R2`，再对两个检查点运行 `evaluate.py`。`arm_queue.sh` 按相同训练和验证入口执行两个种子。`analyze.py` 与 `diagnose.py` 重建各项验证端点，`training_panel.py` 重新生成训练图的候选，`after_tool_probe.py` 在固定工具结果的条件下比较第二轮候选。本地 `combine.py` 汇总两个种子，`timing.py` 读取上一轮结果进行配对比较，`verify_local.py` 验证模型和逐图输出并独立复算召回。

主运行和 repeat 各自的 records 保存训练日志、初始化指纹、模型指纹与验证输出。压缩归档只含本轮新生成的 R1、R2 验证轨迹与特征。R0 归档和上一轮的权重身份见[上一轮实验](../E3-2_UCM冷启动三组短训_20261123/实验结果.md)。软件版本、原始权重与数据指纹见 [环境记录](records/provenance.json)。
