# CUP 与 E1 对照的来源

Wang 等人的《Cross-Modal Remote Sensing Image–Text Retrieval via Context and Uncertainty-Aware Prompt》在图 2 给出 CUP 的三个组成部分：提示生成模块 PGM、融合提示的冻结编码器 RSP-CLIP、不确定性估计模块 UEM。PGM 中的上下文聚类块 CCB 从遥感图像提取对象级信息，以生成视觉先验提示；可学习提示、提示融合和用于训练的 UEM 均属于 CUP。本文的诊断分数取已训练检索器输出的归一化图文嵌入余弦。 [CUP 论文](../../../Cross-Modal_Remote_Sensing_ImageText_Retrieval_via_Context_and_Uncertainty-Aware_Prompt.pdf)

本机 Claude Code 项目会话 `139e7c5b-cae2-4f9f-9cec-63a6c4dff809` 第 374 行来自 VS Code（2026-09-05），将当时的改造描述为以 Agent 上下文先验替代 CCB，同时沿用原有不确定性机制。会话随后提到的 Agent 置信度接入属于讨论中的建议。实际实现中，`use_agent_prior=False` 调用 `cluster_model(img)`，开启后改用 `agent_proj(agent_hidden)`，随后继续执行原有提示融合与检索编码。 [仓库实现](../../../CUP/vilt/modules/vilt_module.py#L584)

| 对照 | 本轮使用的生成与检索设置 | 依据 |
|---|---|---|
| CLIP | 冻结 ViT-L/14，不插入视觉或文本提示 | 提示长度 0，在仓库 CLIP 实现中拼接空序列 |
| CUP（CCB） | 项目复现的聚类先验版，严格读取 UCM version_12，直接从图像计算 CCB 先验 | 归档 `pipeline_ccb_eval.sh`、`ccb_features.py` 与 `ucm_ccb_clustering_prior.ckpt` 的配置和权重哈希 |
| ASPF（重建） | Qwen 基座、无 LoRA 和工具，纯推理系统提示；使用以纯推理缓存训练 50 轮并预先冻结的读出权重 | 历史纯推理原检查点缺失，使用 11 月 13 日冻结的重建模型 |
| 原始 AGSE 权重 | 历史 UCM 主 LoRA、原工具协议、域内场景分类器、UCM version_2 检索权重 | 归档主方法、原 rollout 和严格加载的 `ucm_main_domain_tool.ckpt` |
| 旧 CLIP 口径（衔接检查） | 视觉侧插入 16 个全零 token，复算旧 E1 | 原 E1 打分代码、旧数量得分 |
| 原始 AGSE 归档先验（补充） | 同一个 version_2 检索器，读取历史每图与首条原始描述生成的缓存 | 和通用查询行分列，以记录输入和生成条件的差异 |

ASPF 与 AGSE 共用面向当前图像的查询 `Describe the visible scene.`，各自沿用自己的系统提示、生成模型与读出权重。AGSE 的系统提示沿用固定港口演示，按历史 E1 的置信阈值 0 接收模型请求的工具反馈。二者均为贪心解码，每轮最多 64 个新词元、最多 3 轮，提取最后一次生成调用最后一步的末层末位置状态。模型行之间的比较包含检索器训练和生成路径等差异。
