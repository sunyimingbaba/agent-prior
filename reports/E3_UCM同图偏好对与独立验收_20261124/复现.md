# 从原始候选和一次生成轨迹复核

本目录沿用同一 Git 历史内的三个相邻报告目录。两套原始第二轮 R2 起点来自「E3-2_UCM回填后回答训练_20261124」，训练侧 168 张图、文本编号和冻结系数来自「E3-1_UCM第二轮R3困难负样本复验_20261124」，122 图、原始贪心向量和普通验证图库入口来自「E3-2_UCM有效图组定向短训_20261124」。完整 UCM 测试图库的清单与旧 R2 记录来自「E3-2_UCM与RSITMD独立复验_20261124」。项目根目录中的 AGENTS.md 说明了图像级先验的实际输入。

## 在本机重算

在本报告目录运行下列命令。Python 需要 NumPy、SciPy 和 PyTorch；重建原图清单另需 PyArrow、Pillow、OpenCV 和项目原始 Arrow 数据。锁定清单随报告保存，已有读出复核可直接使用。

```bash
export OPENBLAS_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1
python3 code/build_pairs.py
python3 code/teacher_audit.py
python3 code/dev_metrics.py observed hard native
python3 code/dev_metrics.py continuous joint continuous_native
python3 code/dev_metrics.py bounded bounded
python3 code/audit_fit.py
python3 code/check_dev.py
python3 code/candidate_guard.py
python3 code/guard_score.py
python3 code/multi_caption.py train fresh independent
python3 code/recheck_reward.py fresh independent
python3 code/anchor_gap.py fresh
python3 code/anchor_gap.py independent
python3 code/relative_teacher.py fresh
python3 code/relative_teacher.py independent
python3 code/swap_score.py fresh
python3 code/swap_score.py independent
python3 code/score_replica.py
```

两份种子在每一张图上先取均值，细节指标按原始图对重采样，普通全库 mR 按源图重采样，固定随机数做 20,000 次。候选实验的普通指标 MRR 使用留出的原生描述和另一半普通负图库。实际候选中重复的回答按其在采样位置中的频次参与并列期望，逐图数据保留小数票。原首句分档实验与多描述实验有不同的留出正描述集合，两者的 MRR 使用各自表内的对照。

`recheck_reward.py` 逐档排序复算最终赢家、倒数名次和按图对的区间，核对候选、读出、文本、图片及两份种子的对应关系。`audit_fit.py`、`audit_bound.py` 和 `check_return.py` 分别复核每步训练条件、名次约束和所回传的先验与适配器。适配器目录以本机 `/Users/botlv/cup-deploy-assets/e3-ucm-paired-preference-20261124` 作为参数传入后两条脚本。对已运行阶段检查所有 SHA-256。若有独立模型验收，另设 `E3_NOMINATION=nomination_bounded.json` 运行 `code/score_blind.py`。

## 在学校服务器重放

实验根目录为 `/private/AGSE_E3_1_rebuild_20261112/paired_answer_preference_20261124`。GPU 使用 RTX 5090，Agent 使用 Python 3.13.13、PyTorch 2.10.0 和 CUDA 13.0。冻结 CUP 与代理读出使用另一套 Python 3.12.6、PyTorch 2.4.1 环境，在 CPU 上按 FP32 计算。环境、两套起点与原评分器摘要见 `records/environment.json`。原模型、工具、数据和权重保存在私有挂载上，适配器另有本机备份。

- `code/observed.sh` 生成两组起点参照，再对每个种子完成两臂 32 步偏好训练。`dev_eval.sh`、`read_pair.py`、`pack_stage.py` 依次生成、读出和归档各套权重的自由贪心轨迹。`propose_text.py` 与 `text_read.py` 完成训练图上的文字干预，`gradcheck.py` 在两张训练图上做有限差分。
- `continuous_queue.sh` 启动四套 84 步权重。`bounded_queue.sh` 配合 `bounded_cpu.sh` 生成初始参照、训练两套 168 步权重并读出。每次更新在同场景天然正反图对上计算，原始首句和只给场景的提示分别进入同一个 Agent。
- `guard_queue.sh`、`guard_cpu.sh` 对开发图采样及读出。`independent_reward_gpu.sh`、`independent_reward_cpu.sh` 在独立候选图重复同一过程。`reward_anchor.sh` 对相同独立图运行两套原 R2 的贪心参照。在首批模型验收揭晓后，`replica_queue.sh` 用锁定的两份权重在候选面板另做一次重复验证。`score_replica.py` 逐项复算贪心起点，并按原有两批图对分别重采样汇总细节结果。每种子每图各有两批八个候选位，实际工具返回来自冻结场景分类器。
- `nominate.py`、`nominate_bounded.py` 根据开发结果登记是否有权重进入独立模型验收。入围时用冻结名单调用 `confirm_queue.sh`、`confirm_reader_queue.sh`，并将新权重和起点同批复核。每个训练、采样、归档脚本的完成文件只代表该阶段正常结束。

独立候选图、独立模型验收图均来自 UCM 训练划分。可按 `rgb_sha256` 核对图像内容，按 `guard/inputs/lock.json` 及两个独立目录下的清单核对图对、工具输入和实验口径。最终采用的主候选协议指纹在 `reward_confirm/inputs/lock.json`，各项单次参照与先验互换补充试验另有登记。
