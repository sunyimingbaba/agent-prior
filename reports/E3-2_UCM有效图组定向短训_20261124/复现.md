# 运行与复核

本轮直接继承上阶段的两份第二轮 R2 适配器、场景工具、冻结 CUP 读出器和代理分映射。上阶段在同一仓库的 `reports/E3-1_UCM第二轮R3困难负样本复验_20261124`，其 `records/provenance.json` 包含权重和依赖代码摘要。本轮服务器根目录为 `/private/AGSE_E3_1_rebuild_20261112/r3_informative_groups_20261124`。GPU 和 CPU Python 的绝对路径见 `code/train_queue.sh`。原始数据与模型采用用户已有的私有挂载。以下次序可在新建实验目录重放。

1. 从上阶段开发图读取每图两个八候选批次，从上阶段复核图读取首个八候选批次。对后者新建 `screen` 运行根，引用前次复核的锁定清单、口径、工具结果和文本库。在这个运行根下调用前次 `sample_panel.py a --extra` 和 `b --extra`，CPU 运行 `read_panel.py --extra` 并以 `pack.py --extra` 归档。设置 `E3_PANEL_ROOT` 指向该运行根。新增的两份候选归档与来源摘要在 `screen/records`。
2. 在本机以 `code/panel_assets.py <临时图册目录>` 生成剔除早期图像后的训练图缩略图。图对与 E 模板基于目视标注，在打开本轮新图读出之前经 `code/fresh_panel.py` 固定。机器记录在 `inputs/panel.json` 和 `inputs/lock.json`。复现机若路径不同，可调整 `panel_assets.py` 的本地 Arrow 路径。
3. 在新运行根建 `inputs`、`records`、`scratch`、`pilot`、`results` 并拷入本轮代码和锁定文件。运行 `bash code/train_queue.sh` 生成两个训练名单、两份冻结首轮上下文和八个适配器。每步三批的全部动作、两种细节分差、普通分差、代理名次以及所选批次和实际梯度范数均在 `pilot/<种子>_<组名>/steps.json`。已完成权重由同目录的 `complete.json` 校验。
4. CPU 使用 `code/text_bank.py` 编码新图验收文本。GPU 运行 `bash code/eval_queue.sh`，它会在训练完成后计算实际场景工具结果，依次对起点与最终模型逐图贪心生成。新图输入仅含同类共享的场景提示，普通验证使用既有每图第一条描述及冻结图库。工具结果就绪后 CPU 运行 `code/vectors.py`，将每幅源图单个先验送入冻结 CUP。另运行 `code/archives.py` 校验并打包完整轨迹。起点在普通验证集的向量另从先前已逐图校验的原始记录读取。
5. 将 `inputs`、`screen/records` 的归档和摘要、`records` 的两份上下文、文本向量和工具反馈、`pilot` 的训练记录、轨迹归档、验证向量、归档摘要复制回本机。八套适配器位于本机 `/Users/botlv/cup-deploy-assets/e3-ucm-informative-groups-20261124`，在服务器运行根的 `pilot/<种子>_<组名>/adapter` 也留存。
6. 本机依次运行 `python3 code/verify_screen.py`、`python3 code/score.py` 和 `python3 code/verify.py /Users/botlv/cup-deploy-assets/e3-ucm-informative-groups-20261124`。可从逐图结果重算每项统计。固定图库每图关联五条描述，I2T/T2I 各自 R@1、5、10 后取六项均值。普通检索区间按源图重采样并保持原图库，两种子在图内平均。新图保持自然对成组重采样，三个措辞在图内平均，区间均取 20,000 次重采样的 2.5% 和 97.5% 分位数。区间反映图像抽样变化，只有两份策略种子。

训练池的事后复算入口为 `code/batch_repeatability.py`，使用原两批候选统计跨批复现。预登记的覆盖分层复算见 `code/coverage.py`。运行时环境在 `records/runtime.json`，CPU 读出修正后的源文件摘要另存为 `records/vector_source.sha256`。
