# UCM 格式奖励实验复现

正式运行目录为 `/private/AGSE_E3_1_rebuild_20261112/format_deterministic_20261120`。Python 为 `/private/AGSE_E1_20261110/legacy/env/bin/python`。上阶段路径为同级的 `matched_policy_20261120`，默认数值设置的预运行在 `format_matched_20261120`。共享资产、GPU、包版本与冻结检索器的哈希见 `environment.json`。UCM 的正式测试集留待最终评估。

1. 在新工作目录保存本包的 `code/`、`inputs/`，建立 `logs/`、`results/`、`scratch/cache/torch/kernels/`。训练前检查 `inputs/lock.json`。训练使用 24 张固定训练图、每图 8 条候选、两套候选采样种子。目标描述和反向关系描述只用于打分，Agent 输入为场景提示。
2. `bash code/train_queue.sh` 开启确定性计算，先从相同起点各运行种子 A 的两组三步，核对前缀，再从保存的 AdamW 和 BF16 权重恢复训练。每组落盘第 6、12、24 步的 PEFT 适配器，末步保存优化器状态。训练凭据包含逐步参数指纹、原始动作 token、逐 token 对数概率、两项语义分差、格式奖励、组内优势和梯度重放误差。
3. `bash code/eval_queue.sh` 等待对应权重落盘，逐一覆盖原首句、全图通用查询、双物体关系题。历史起点从已核验的相同评估程序的输出共用，也可用 `python code/evaluate.py base 0` 从空目录重新生成。单次部署逐图保存每轮生成 token、工具事件、BF16 先验和冻结检索器的图像向量。种子 B 的最终权重执行首轮首 token 屏蔽结束符的预设干预。同一干预在种子 A 上的补充复验记录于 `inputs/decoding_replication.json`，执行 `bash code/replicate_queue.sh`。两种子均保留全部结果。
4. `bash code/post_queue.sh` 核验真实格式分、各组训练和权重，执行统计、另一种最高正样本排名算法及部署复核。单独重算用 `python code/analyze.py`、`python code/crosscheck.py`、`python code/check_deployment.py <上阶段完整目录>`。成对区间固定图库，对同一源图重采样 20,000 次。两训练种子先在同一源图上取平均，再做源图重采样。E1 数量按图重采样，属性和关系按原始反向图对重采样。`inputs/e1_extension.json` 记录补充分析范围和冻结 E1 文件。
5. `python code/numerical_control.py <上阶段目录>` 核对默认内核的同种子复跑。预运行结果单独存入 `numerical_control/`。主报告采用正式运行结果。
6. 本机及私有挂载保存中间和最终权重与末步恢复状态。Git 保存评估数据、代码、结果、日志及最终权重相对历史 LoRA 的差分。按 `results/weight_restoration.json` 指定的差分目录执行 `python code/adapter_delta.py restore <历史adapter_model.safetensors> <差分目录> <新的输出文件>`，配合同状态记录的 adapter_config.json 使用。全目录在完整副本上可用 `python code/manifest.py --verify` 核对。
