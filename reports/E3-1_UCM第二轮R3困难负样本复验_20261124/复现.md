# 输入、运行与复算

**本轮目录**在学校 5090 的私有挂载目录 `/private/AGSE_E3_1_rebuild_20261112/r3_after_tool_trainpanel_20261124`。用前次实验保留的两个第二轮 R2 适配器和原环境，依赖脚本的 SHA-256 见 records/provenance.json。训练划分和预先锁定的图对、A/B/C（复核组另有 D）、类别提示可在 inputs/panel.json 和 confirm/inputs/panel.json 中逐图检查。复核图像的地域来源信息未提供，几何筛查只覆盖可以匹配的重叠裁块。原始标签均由助手在查看相应得分前目视核对，尚待独立人工复核。

1. 本机运行 code/manifest.py 和 code/confirm_panel.py，以原始 Arrow 总目录作为参数，重建两个面板。将代码及锁定后的清单同步至服务器并在每个运行根下建好 scratch、records 和 results。基础依赖与上阶段一致。GPU 使用 `/private/AGSE_E1_20261110/e1_prior_compat_20261111/venv/bin/python`，CPU 使用 `/private/AGSE_E1_20261110/legacy/env/bin/python`。
2. 开发组调用 code/run.sh，同时用 CPU 运行 code/read_panel.py。对同图追加采样时，两份权重分别运行 code/sample_panel.py a --extra 与 b --extra，CPU 运行 code/read_panel.py --extra。复核组以 E3_PANEL_ROOT 指向 confirm，沿用 prepare、a、b 的采样顺序和 CPU 读出。每图首轮采用实际部署流程，若未调用工具，则把它的单一固定先验记为 8 个相同的候选位，保持图像权重。重复位保留以反映采样分布。
3. 用 CPU 执行 code/pack.py，开发组补充采样另执行 code/pack.py --extra。code/analyze.py 的 main、extra、combined 模式分别评价初次 8 条、追加 8 条、合并 16 条。主比较的最高奖励出现并列时按均匀选择记期望得分。code/learning_signal.py 读候选 CSV 复算原训练的优势向量，检查改选是否只是所有分数拉平。code/continuous.py 先在开发面板锁定尺度，再对指定结果目录运行。code/verify.py 在本机从逐候选向量和文本向量独立重算原赢家、25%、50% 以及连续 R3 的赢家、验收判别及普通 MRR。
4. 下游短训运行 code/pilot.sh。用 code/pilot_eval.sh 为全部最终检查点生成一次贪心先验，CPU 并行运行 code/pilot_vectors.py 读出。两个起点的 UCM 常规验证直接核对上轮归档的逐图输出。code/pilot_score.py 的参数是历史 paired_views 的 inputs 目录；本地对应 `reports/E3-2_UCM双视图方位奖励_20261120/inputs`。code/pilot_archive.py 打包新生成的贪心轨迹。code/pilot_verify.py 以同一 inputs 和本机检查点备份目录为参数，验证原始轨迹、检查点及六项方向召回。
5. 学习记录中的每一步保留第二轮采样 token、第三轮续写、代理排名、普通与困难负样本分差、实际奖励、优势与梯度范数。短训开跑时一次 CPU 子进程在建立通信前输出依赖日志，首次启动在第一个优化步骤前退出。修正标准输出重定向后从原权重重启，正式四组各自从头运行。
