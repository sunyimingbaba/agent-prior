日期：2026-11-13。使用上一项相同的 181.tif、984.tif、2088.tif（UCM val 第 10、95、207 行）。独立保存诊断，原项目源码、模型、先验及既有实验结果保持原状。

## 已定位的两个环节

本次完成 42 项受控生成，并在本机复核状态、词元序列和选定概率。

1. **首轮采样直接结束**：上一项的 11 个空轨迹均只生成了 ID `151645`（`<|im_end|>`）。本次相同输入、温度 1.0、seed 0 下，3 张图在启用和停用 LoRA 时均再次首步结束。启用 LoRA 时，这一步实际采样分布中的 EOS 概率为约 24.72%–39.03%。
2. **工具结果回填的消息边界**：原程序将工具调用文字和 `<result>` 直接拼接到仍处于 assistant 角色的输入末尾。固定同一张图、同一条查询、同一份实际工具结果，改用完整的 assistant 调用消息、user 结果消息及新的 assistant 生成前缀后，6 次续写（3 图 × LoRA 开/关）均得到完整 `<answer>...</answer>`，且均未含 `addCriterion`。

LoRA 的 584 个张量加载后与保存文件的键、形状和数值逐项一致，运行前后适配器权重哈希相同。停用 LoRA 的原流程也出现相同类型异常，后续排查重点因此放在生成终止与消息组织上。

本步提供生成协议的诊断证据。下一项将把消息重建逻辑放入独立候选生成脚本，预先固定首轮空输出的处理规则，再验证同图多候选的生成质量和检索收益。

## 固定对照设计

方案在本轮生成前保存为 `预先固定诊断方案.json`，服务器同内容文件为 `plan.json`。

**24 项原流程对照**：3 张图片 × LoRA 启用/停用 × 工具提示/纯推理提示 × 贪心/温度 1.0 采样。均使用 seed 0、原 `rollout_one`、每轮最多 64 个新词元、最多 3 轮，工具阈值 0.0。先验仍取最后一次生成调用的最终解码步骤、末层末位置。

**18 项固定工具结果后的续写对照**：3 张图片 × LoRA 启用/停用 × 3 种回填形式。每图使用同一份真实域内场景分类结果，保持图片、查询和模型固定，使用贪心续写：

| 回填形式 | 工具调用文字 | 结果所在消息与续写方式 |
| --- | --- | --- |
| `raw_unclosed` | 保留原输出的未闭合 tool_call | 按原代码追加结果文字 |
| `raw_closed` | 补齐 `</tool_call>` | 继续按原代码追加结果文字 |
| `chat_closed` | 完整 tool_call | assistant 调用消息结束 → user 工具结果消息结束 → 新 assistant 生成前缀 |

最后一组使用原处理器的 `apply_chat_template` 重新渲染消息，其消息角色与原提示中已有的 few-shot 示例一致。此组测量给定工具调用和结果之后的续写；首轮自由采样的结果单独记录。

本次有效的对照上下文依次包含：

