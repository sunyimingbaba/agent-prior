# 本机离线复现

本阶段使用Python3.12.7、PyTorch2.11.0、NumPy2.4.4和Matplotlib3.10.9，实际解释器版本以 `runtime.json` 为准。计算设备CPU，CPU数学线程2。GPU生成、模型训练和文本特征编码均沿用父阶段封存结果。

## 输入与执行

`plan.json` 在数值分析前固定。`inputs/source_manifest.json` 保存10份父文件的哈希；其中完整父证据包作为来源锚点，另外9份输入复制至 `source_data/`。证据归档中包含这9份副本、4条关键轨迹原文件，以及本阶段执行源码。

首次准备输入可在父阶段仍位于同级目录时执行：

```sh
python3 code/prepare_inputs.py
```

从交付证据包解压到一个新的目录后，以下CPU命令可直接重建本阶段结果：

```sh
python3 code/analyze_multineg.py
python3 code/build_case_review.py
python3 code/verify_multineg.py
python3 code/plot_multineg.py
python3 code/build_report.py
```

`build_case_review.py` 优先读取本机父阶段的原始轨迹，父目录缺失时使用归档中已校验的 `case_traces/`。关键案例按本轮离线结果选取，人工生成文本事实准确性保持 `[待确认]`。

为保留当前输出，可执行：

```sh
python3 code/reproduce_offline.py
```

该程序将输入、源码和关键轨迹复制到新的临时目录，依次执行分析、案例整理和独立核验；核对数值分析树和14份结果文件。结果记录在 `打包材料重放核验.json`，临时重放材料保留。

## 数值与原始文件

主要分数采用父阶段保存的float32相似度；独立核验用保存的图像/文本特征重算float64点积。原训练组优势使用历史GPU float32均值/标准差重建；新奖励的优势为CPU float32离线反事实。

CSV中使用图像配对的10,000次重采样，数量1–4宏平均逐数量分层抽样。先验控制固定在各策略的102.tif贪心轨迹。B预言机和候选覆盖仅用于诊断；原人工数量、完整失败轨迹与所有候选均保留在来源或证据中。

`analysis_attempts.json` 保留两次输出前中止的实现修正记录；方案、输入和统计规则保持原哈希。`code_hashes.json` 封存最终执行源码，`file_checksums.json` 保存证据内逐文件哈希。归档位于本机和GitHub；服务器副本状态见 `备份校验.json`。
