# 状态协议修正方案（待在新训练入口实现）

本轮已完成 18 条原回答与 6 条延长回答的冻结模型核验。下一版训练入口优先统一以下三个部分。原训练入口、模型、缓存和结果保留原文件，新版本单独存放并记录源文件哈希。

## 1. 奖励状态直接来自同一次生成

沿用当前检索模型与离线缓存所使用的状态规则：最后一次 `generate`、最后一个有效解码步骤、最后一层、最后位置。生成时保存该隐藏态及其实际输入 token、最后发出 token、解码步数和哈希，奖励直接使用这份隐藏态。

对没有生成后补齐的单条序列，设提示长度为 P、实际生成步数为 N，则该状态对应完整序列下标 P+N-2。本轮已核对该索引。完整前向的倒数第二位置与原状态的余弦非常接近，仍在 18 条中改变了 7 条代理排名和 4 条实际检索排名。因此，奖励链优先复用原生成隐藏态，完整前向按位置重算作为诊断辅助。

批量生成时，逐条记录首次停止的位置，按各自有效解码步骤提取隐藏态。相同图像和上下文的单条/批量数值差异另行记录，验收以生成状态到奖励、缓存的逐位传递为主。

## 2. 梯度前向使用有效回答掩码

单独重算策略 log probability：提示与工具回填结果只提供上下文，模型生成的有效回答 token 参与对应轮次的损失；首次结束 token 参与该轮次的生成概率，结束后的右侧填充权重为 0。注意力掩码与有效序列长度对应，批量长短变化时保持单条回答的奖励状态与有效损失 token 集合一致。

每条轨迹保存有效生成长度、结束 token、填充数量、响应掩码数量及 log probability。核验短回答追加填充后有效 log probability 保持一致，并检查奖励状态哈希保持一致。

## 3. 训练与缓存共享真实工具流程

训练采用“模型生成调用 → 执行已注册工具 → 保存并回填真实结果 → 模型继续生成”的流程。工具返回值保留来源与置信度；回填文本作为上下文，工具动作和最终回答等模型实际生成部分分别保存 token 与损失掩码。纯推理模式使用明确传入的系统提示。

本轮数字来自固定真实工具上下文，用于分离状态位置和长度影响。下一版工具流程验收另记录实际工具调用数、消息角色顺序和逐轮输入输出。

4. 用相同验证图像检查更新前后完整回答质量、奖励和下游检索收益，再确定训练长度。
