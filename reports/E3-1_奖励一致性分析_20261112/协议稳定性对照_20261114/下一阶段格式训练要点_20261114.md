# 下一阶段格式训练要点

本文件记录当前协议对照引出的后续设计，实际训练参数与结果将在新方案和新目录中固定。

## 已观察到的行为

三个校准对照各 60 条采样，协议合格率分别为 6.67%、60%、70%。工具 token 诊断显示，三组中都出现注册工具名之后直接结束回合的情况；三组 180 条采样的生成轮次中，工具结束 token 的出现次数为 0。完整结束标签经同一 tokenizer 编码、解码可完整保留，诊断保存在 `tool_terminal_diagnosis.json`。

## 格式训练的小实验

沿用本轮 train 15 作为训练图、其余 train 63 作为确认图，原 E1 val 22 继续作补充诊断。使用新 LoRA 目录保留原 c742 模型。实际输入继续采用统一中性文本，人工数量标签继续用于后续评分。

首先为完整的注册工具调用与回答标签建立可学习的监督路径：训练第一轮生成完整调用；工具结果使用实际分类器返回的独立消息；随后训练完整的 answer 边界。格式损失的 token 位置、正文内容来源、EOS 位置、工具回填位置及各轮参与范围在训练前写入方案。若使用正文内容作为上下文，逐条记录来源，并将正文学习与格式 token 的学习分别说明。

先验证带完整调用的监督预热，再决定是否接入严格格式奖励。每个实际优化步骤都保存损失、梯度与参数哈希，训练与固定策略评价分别记录。

## 训练入口的概率核对

本轮优化器更新数为 0，保留的历史 `response_logprob` 函数用于追溯旧温度 1 流程。后续若采用温度 0.7 采样，新增训练实现须按同一温度缩放 logits，并重现首 token EOS 屏蔽，逐 token 验证生成分布与重算对数概率。实际工具返回文本和图像 token 的监督范围单独核对。

## 确认与汇报节点

沿用本轮 train 63 的协议确认条件，另报完整工具调用数、真实工具使用率、B 数量句对和完整图库指标。最终形成一个包含训练、固定策略确认、独立复算和检查点备份的完整节点。原数量训练的 7 项条件继续单独核对。
