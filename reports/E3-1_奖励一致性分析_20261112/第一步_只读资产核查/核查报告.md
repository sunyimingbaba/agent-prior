## 三、奖励实现与历史记录

### 3.1 当前源码的实际评分链

`CUP/agent/grpo/scorer.py` 第 108—124 行实际执行：

```text
候选隐藏状态（3584）
→ agent_proj（1024）
→ 扩展至 16 个位置并与视觉 prompt 融合
→ 全零图像 + visual_prompt 进入 CLIP 视觉塔
→ 与 210 张缓存图像特征比较
→ 目标图像名次 rank（从 0 开始）
→ R_retrieval = 1 / (1 + rank)
```

源码顶部及 `score` 的文档字符串仍提到“文本塔”，实际执行路径为视觉塔。本次记录这一注释与执行行为的差异，代码保持原样。

总奖励由 `reward.py` 定义为 `R_format + λ × R_retrieval`。历史脚本使用 `reward-mode=soft`、`λ=1.0`。后续应分别保存名次、检索奖励、格式奖励和总奖励，再对各项与实际检索表现的关系分别分析。

### 4.1 两份缓存的内容

`grpo_val_cache.pt` 与 `grpo_val_cache_best.pt` 均只保存 `image_features` 和 `image_indices`：

- 特征形状均为 210×768，dtype 为 float32，数值全部有限。

- 两份缓存的特征张量逐元素完全相同，最大绝对差为 0。
