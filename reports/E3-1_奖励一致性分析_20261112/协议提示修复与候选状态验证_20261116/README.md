# 协议提示修复与候选状态验证（2026-11-16）

本轮固定原均衡32步Agent与四个val选择的读出模型，先审计实际SFT/RL监督和工具角色，再仅用train63的协议结果选择中性/轮换提示。候选状态取自实际generate的最终层解码步骤，完整保存原始逐步状态与token位置。测试集既有评分继续封存；原始资产完整性核验包含test产物的字节哈希读取。

`protocol_plan.json` 封存三种提示、train63选择门槛、273图状态队列、6个状态家族、20次置换、共享状态及270组评分记录。候选提示按固定顺序取首个达到协议门槛的设置：无示例强顺序约定、中性格式示例、训练图真实分类反馈构成的三场景轮换示例。选择使用协议完成与实际请求工具的结果，检索/数量分数和val结果留待选择后分析。

三种提示均保留模型自行生成工具调用，工具反馈在实际请求后回放此前核验的真实分类结果。若三种提示均未通过，执行预先固定的30次格式监督更新，再按相同训练集门槛选择提示；原检查点保留，新增模型单独归档。具体分支与实际更新数以运行结果为准。

候选状态包括原末有效步骤、真实工具回填后回答回合的首个generate步骤，以及答案正文输入token对应步骤的均值。每个已生成token j在步骤j+1进入模型；均值按真实byte-level token字节位置定位，float64计算后转BF16。缺失状态使用同轨迹末状态回退并记录覆盖率，全部案例保留。

环境沿用账本与原解释器 `/private/AGSE_E1_20261110/legacy/env/bin/python`；新输出目录 `/private/AGSE_E3_1_rebuild_20261112/protocol_prompt_state_validation_20261116`。生成入口 `code/run_generation.py`，先核对旧证据、包版本、CUDA见证、30个SFT目标掩码及273条已有答案token位置，再进行两锚点与全273旧状态精确重放。
